# 安全与信任边界

涉及输入处理、身份权限、凭证、文件、外部请求或模型输出时读取本页。安全不是审查阶段补的一轮扫描，而是在写下第一行拼接字符串时就该成立的约束。

深度判据见 [threat-modeling](threat-modeling.md)、[llm-application-security](llm-application-security.md)；本页只保留速判与路由，细节不在这里重复。

## 先画信任边界

浏览器参数、请求体、头部、Cookie、上传文件、第三方回调、URL 中的跳转目标、被读取的配置、以及模型的输出，一律视为不可信，在服务端每个入口重新校验。前端校验是体验，不是控制；隐藏按钮、注释掉的入口、只在客户端判断的角色，都不构成权限。

内部服务之间也不是默认可信：来源地址可以伪造，内网可达不代表调用方有权限。跨服务调用同样需要身份与授权，不因为“在内网”就跳过。

## 认证、授权与归属

会话有效只说明“是谁”，不说明“能操作什么”。每个对象级操作单独校验归属与租户范围，列表接口同样要过滤，不能只在详情页判断。批量接口按每条记录校验，防止夹带他人 ID。管理接口、导出接口、文件下载链接单独检查，这些位置最常见“列表过滤了但下载没过滤”。对象标识用不可枚举的键或显式授权，不靠“猜不到 ID”当保护。

## 注入类问题按汇点处理

- SQL：值一律参数绑定；表名、列名、排序方向等无法绑定的部分用白名单映射，不拼接用户字符串。
- 命令与脚本：用参数数组调用，不拼 shell 字符串；确实需要 shell 时对每个参数做转义并列出允许的字符集。
- HTML 与模板：按输出上下文转义（元素内容、属性、URL、脚本、样式各不相同）；富文本走白名单净化，不用正则黑名单过滤标签。
- 路径：解析成真实路径后再判断是否在允许根目录内，比较分隔符边界；字符串前缀比较挡不住 `..`、符号链接和大小写差异。
- 出站请求：对用户可控的 URL 限制协议与主机，解析后的地址再拦内网与元数据地址，并禁止重定向跟随到受限目标；抓取类功能还要限制体积与超时。
- 反序列化与模板求值：只接受白名单类型或带签名的数据，不把外部输入交给能执行代码的反序列化器。

## 凭证与秘密

凭证只在服务端从文件或秘密存储读取，带权限的最小范围、可轮换；不写进前端产物、源码、日志、错误信息、URL 查询串或提交历史。示例与测试用明显的假值，避免形似真实密钥被误用。需要本地调试时给出读取路径和环境变量名，不要求把明文贴进对话或配置文件。

## 会话、跨站与上传

Cookie 使用 HttpOnly、Secure 与合适的 SameSite；跨站写操作配合 CSRF 令牌或同源校验，不依赖“攻击者不知道接口”这种假设。多步敏感操作校验当前凭据或在关键步骤重新认证。

上传文件校验大小、类型与内容，不只信客户端 MIME 和扩展名；随机化存储名，存储目录不具执行权限，图片等可解析格式做解码校验。对外提供下载时校验请求者权限，并防止通过路径参数读取任意文件。

## 依赖与供应链

新增依赖先看维护状态、最近发布、安装脚本行为和依赖树体积；锁文件变更单独审视，避免为一个小功能引入整棵新树。升级安全相关依赖时核对破坏性变更，不因为“顺手升到最新”替换掉项目原有版本约束。私有源与镜像要确认来源可信。

## 把模型输出当作外部输入

LLM 应用里，模型输出与用户上传的文档、检索到的网页一样不可信。不要把输出直接拼进 SQL、命令、文件路径或未转义的 HTML；工具调用的参数与目标要经过白名单与权限校验，模型无权替用户扩大范围。检索内容与文件可能携带注入指令，需要与系统指令隔离并标明来源。输出可能包含密钥或他人数据，返回前过滤；对外提供的能力要有速率、成本与超时上限。

## 发现疑似漏洞时

先确认可利用路径：不可信来源是否能到达危险汇点，中间有哪些校验，攻击者实际能控制到什么程度。静态扫描提示、可疑函数名、缺少注释都不足以判定漏洞。给出最小复现和影响范围，标明是推断还是已验证；不在生产数据上执行破坏性验证，需要时用隔离环境或只读方式取证。

没有发现时说明检查过哪些入口和汇点，以及未覆盖的部分，不写“已确认安全”。
